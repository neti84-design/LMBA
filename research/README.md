# 현장 조사 — 구글 폼 만들기

`create-google-forms.gs` 를 **본인 구글 계정에서 한 번 실행**하면 아래가 통째로 생성됩니다.

| 만들어지는 것 | 용도 |
|---|---|
| **① 관찰 기록 폼** | 팀원 6명이 매일 3회 네이버 예약 잔여 슬롯을 찍는 폼 |
| **② 사장님 설문 폼** | 인스타 DM 으로 보낼 17문항 설문 (1~2분) |
| **응답 스프레드시트** | 두 폼의 응답이 한 파일에 모임 + `매장 마스터` · `안내` 탭 |

실행한 계정이 소유자가 되므로 **응답은 전부 그 계정으로 들어옵니다.**
두 폼 다 **로그인 없이 응답**할 수 있습니다.

---

## 실행 방법 (5분)

1. **[script.google.com](https://script.google.com)** 접속 → 좌측 상단 **새 프로젝트**
2. 편집기에 기본으로 들어 있는 `function myFunction() {}` 을 **전부 지우고**,
   `create-google-forms.gs` 내용을 **전체 복사해서 붙여넣기**
3. 💾 **저장** (Ctrl+S)
4. 상단 함수 선택 드롭다운에서 **`전체생성`** 을 고르고 **▶ 실행**
5. 처음 실행하면 권한을 묻습니다 — 아래 순서로 통과하세요

   > **권한 검토** → 본인 계정 선택 → **"Google에서 확인하지 않은 앱입니다"** 경고가 뜹니다
   > → 좌측 하단 **고급** → **`제목 없는 프로젝트`(안전하지 않음)으로 이동** → **허용**
   >
   > 본인이 방금 붙여넣은 스크립트라 정상입니다. 구글은 외부 배포용으로 심사받지 않은
   > 스크립트에 이 경고를 일괄로 띄웁니다. 요구하는 권한은 **폼 · 스프레드시트 · 드라이브 생성** 뿐입니다.

6. 실행이 끝나면 **실행 로그**에 링크 6개가 찍힙니다.
   같은 링크가 새로 생긴 스프레드시트의 **`안내` 탭**에도 들어 있습니다.

## 실행 직후 반드시 확인할 것

### ✅ 로그인 없이 열리는지 확인

**시크릿 창(새 크롬 → Ctrl+Shift+N)에서 응답용 링크를 열어 보세요.**
로그인 화면 없이 바로 문항이 보이면 정상입니다.

개인 Gmail 계정으로 만들면 기본값이 "로그인 불필요"라 그대로 됩니다.
만약 **회사(Workspace) 계정**으로 만들어서 로그인을 요구한다면, 폼 편집 화면에서
**설정 → 응답 → "○○ 및 신뢰할 수 있는 조직의 사용자로 제한"** 을 **끄면** 됩니다.

### ✅ 매장 마스터 채우기

스프레드시트 **`매장 마스터`** 탭에 `N01`~`N50` 코드가 미리 들어 있습니다.
여기에 실제 매장을 채우세요.

| 열 | 채울 내용 |
|---|---|
| 매장명 · 업종 | 네이버 지도에서 찾은 그대로 |
| 담당자 | 팀원 6명 중 한 명 (드롭다운) — **1인당 8~9곳** |
| 등급 | **잘되는 집 / 보통** (드롭다운) — 표본이 한쪽으로 쏠렸는지 볼 때 씁니다 |
| 하루 총 슬롯 수 | 영업시간 ÷ 시술 단위. **공실률 계산의 분모**라 꼭 필요합니다 |
| 네이버 예약 링크 | 매번 검색하지 않게 링크를 박아 두세요 |

> **매장 선정은 한 번만 하고 도중에 바꾸지 마십시오.**
> 표본이 흔들리면 2주치가 통째로 못 쓰게 됩니다.
> **잘되는 집과 보통 집을 절반씩** 섞는 게 중요합니다 — 심사위원이 지적한 역선택 질문의 답이 여기서 나옵니다.

### ✅ 팀원에게 미리 채워진 링크 배포

`안내` 탭 아래쪽에 **기록자 · 회차가 미리 채워진 링크 18개**(6명 × 3회차)가 있습니다.
팀원에게 **자기 이름 줄의 링크 3개만** 보내 주세요. 매번 이름·회차를 고를 필요가 없어집니다.

휴대폰 홈 화면에 바로가기로 저장해 두면 탭 한 번에 열립니다.

## 관찰 규칙 (이게 프로토콜입니다)

| # | 규칙 | 왜 |
|---|---|---|
| 1 | 기록 시각은 **10:00 / 14:00 / 17:00**. 앞뒤 15분을 넘기면 그 회차는 **건너뛴다** | 시각이 흔들리면 회차 간 비교가 무의미해집니다 |
| 2 | **한 번 제출 = 한 매장.** 제출 후 "다른 응답 제출"로 이어서 | 매장별로 행이 나뉘어야 집계가 됩니다 |
| 3 | 휴무 · 접속 불가는 **반드시 그렇게 기록**한다. 빈칸을 0으로 세지 않는다 | **결측을 0으로 세면 가짜 당일 취소가 생깁니다.** 이 조사에서 제일 중요한 규칙 |
| 4 | 오전에 막혀 있던 시간대가 오후에 **다시 열리면 당일 취소 1건**으로 본다 | 사장님께 묻지 않고 취소를 세는 방법입니다 |
| 5 | "남아 있는 시간대"를 **되도록 적는다** (예: `14:00, 15:30, 17:00`) | 숫자만 있으면 4번 판정이 둔해집니다 |

> **4번은 추정입니다.** 사장님이 휴게시간을 푼 경우도 섞입니다.
> 그래서 **DM 설문 Q6(주간 당일 취소 건수)과 대조해서 보정**합니다.
> 발표에서도 "추정치"라고 먼저 말하십시오. 그게 더 셉니다.

**소요 시간** — 매장당 약 15초, 1인 8곳이면 **회차당 2분**, 하루 6분입니다.

## 사장님 설문 (DM 발송용)

17문항, 대부분 한 번 탭하면 끝나는 객관식입니다. 5개 묶음으로 나눠 놓아 길어 보이지 않습니다.
**각 문항이 무엇을 확인하려는 것인지 알고 쓰십시오.**

| 문항 | 무엇을 얻나 | 어느 지적 |
|---|---|---|
| Q1 업종 · Q2 규모 | 세그먼트. **1인샵은 빈 시간의 한계비용이 완전히 0** 이라 반응이 다를 것 | — |
| Q3 예약 채널 | **연동 대상 파악** + 네이버예약 관찰 표본이 대표성 있는지 검증 | F8 |
| **Q4 주간 예약 건수** | **비율의 분모.** 이게 있어야 노쇼율이 계산됩니다 | **F1** |
| **Q5 노쇼 건수** | 노쇼율 실측 | **F1** |
| **Q6 당일 취소 건수** | **당일 취소율 실측 — 시장 규모의 핵심 근거** | **F1** |
| Q7 비는 시간대 | "유동인구 없는 낮 시간" 가설 검증 | F1 |
| **Q8 지금은 어떻게 하시나요** | **진짜 경쟁자가 누구인지 드러남.** 인스타 스토리가 많이 나오면 우리 경쟁자는 네이버가 아니라 인스타입니다 | F3 |
| Q9 할인 수용 의향 | **니즈 자체의 존재 여부** | **F2** |
| **Q10 할인 폭** | **객단가 가정(4만 원 → 2.4만 원, 40%) 검증.** 20%가 한계로 나오면 유닛 이코노믹스를 다시 짜야 합니다 | F1 |
| **Q11 준비 시간** | **"30분 내 도달" 설계의 현실성.** 2시간 필요하다는 답이 많으면 필터 파라미터를 바꿔야 합니다 | — |
| Q12 단골 비노출 | 카니발라이제이션 방어 설계의 근거 | F2 |
| **Q13 안 하는 이유 (주관식)** | **가장 값진 답.** 설계를 바꿔야 할 지점이 여기서 나옵니다 | F2 |
| Q14 3% 입점 의향 | 수수료 조건에서의 실제 수용도 | F11 |
| **Q15 수용 가능한 수수료 상한** | **"수수료 5%면 3년차 흑자"의 실측 근거.** 이 한 문항이 재무 전체를 좌우합니다 | **F1 · F11** |
| Q16 입점 결정 요인 | 무엇을 먼저 만들어야 하는지의 우선순위 | — |
| Q17 문자 등록 방식 | **온보딩 대안의 검증** | **F8** |
| (선택) 통화 인터뷰 동의 | **"직접 뵀습니다"를 만드는 문항.** 5명만 응해도 심층 인터뷰가 생깁니다 | **F2** |

### 이 설문의 설계 의도 세 가지

**1. 노쇼를 비율이 아니라 숫자 세 개로 나눠 물었습니다.**
"10건 중 2건"으로 받으면 집계가 안 됩니다. **전체 건수 · 노쇼 · 당일 취소를 따로 받아
비율은 저희가 계산**합니다. 사장님은 오히려 숫자 하나씩 적는 쪽이 편합니다.

**2. 설득은 안내문에, 질문은 담백하게 두었습니다.**
"0원이 될 시간을..." 같은 표현을 문항에 넣으면 유도 질문이 되고, **심사위원이 그 데이터를 깎습니다.**
서비스 설명은 섹션 안내문에 두고, 문항은 사실만 묻습니다.

**3. "안 한다"는 답이 나올 길을 열어 두었습니다.**
Q9·Q14·Q15에 모두 거절 선택지가 있고 Q13에서 이유를 받습니다.
**긍정만 나오는 설문은 심사에서 신뢰받지 못합니다.**

### 응답률이 낮으면 이 4개를 먼저 빼십시오

Q2(규모) · Q7(비는 시간대) · Q16(결정 요인) · Q3(예약 채널) 순입니다.
**Q4~Q6, Q10, Q11, Q15는 절대 빼지 마십시오** — 이 여섯이 재무와 설계를 바꾸는 문항입니다.

### 개인정보

- 이메일 **자동 수집을 꺼** 두었습니다. 응답은 기본적으로 익명입니다
- 휴대폰 번호 · 이메일은 **선택 문항**이고, 안 적어도 제출됩니다
- 폼 안내문과 제출 완료 화면 모두에 **"기프티콘 발송 후 폐기"** 를 적어 두었습니다. 실제로 그렇게 하십시오
- 발표에서 **"익명 수집, 연락처는 발송 후 폐기"** 를 한 줄 붙이면 됩니다

### DM 문안 (폼 링크와 함께 보내는 짧은 인사)

폼 안내문은 길어도 됩니다. **DM 은 짧아야 열립니다.** 아래를 쓰십시오.

> 안녕하세요 원장님, **[그 가게 얘기 한 줄 — 예: 지난주 올리신 마블 네일 보고 연락드립니다]**
>
> 저는 **다니던 회사를 그만두고 개인 사업을 준비하고 있는 워킹맘**입니다.
> 불쑥 연락드려 죄송합니다.
>
> 예약을 받아 운영하시는 가게들의 **노쇼와 당일 취소, 비는 시간**에 대해
> 작은 서비스를 준비하고 있는데, **제 생각만으로 시작할 일은 아닌 것 같아**
> 현장에 계신 원장님께 먼저 여쭙고 싶어 연락드렸습니다.
>
> **1~2분**이면 되고 대부분 고르기만 하시면 됩니다. **로그인 없이** 바로 되시고,
> 답변은 익명으로 처리됩니다.
>
> [폼 링크]
>
> 답변 주시면 작은 기프티콘 보내드리고, 원하시면 **강남 지역 동종 업계 결과 요약본**도 보내드리겠습니다.
> 바쁘신데 방해드려 죄송합니다. 감사합니다.

**첫 줄은 반드시 그 가게 얘기로 바꾸십시오.** 똑같은 문장을 대량으로 보내면
인스타가 스팸으로 막고, 사장님도 바로 알아봅니다.

발송은 **팀원 각자의 기존 계정으로 하루 10~15건씩**, 며칠에 나눠 보내십시오.
새 계정으로 몰아 보내면 막힙니다. 20개 응답을 받으려면 **250건 정도** 보내야 합니다.

### 화자 설정

스크립트 상단의 `var 소개` 한 줄이 폼 안내문과 DM 의 첫인상을 정합니다.

```js
var 소개 = '다니던 회사를 그만두고 개인 사업을 준비하고 있는 워킹맘';
```

**회사 이름은 넣지 않았습니다.** 회사를 앞세우면 사장님들이 **실제 대기업 사업 제안으로
받아들이고**, 그러면 나중에 곤란해집니다. 개인이 준비하는 작은 서비스로 말씀드리는 쪽이
**응답률도 높고 뒤탈도 없습니다** — 특히 1인샵을 꾸리는 원장님들께는요.

> **한 가지만** — DM 을 보내는 분이 **실제로 그렇게 말할 수 있는 문장**이어야 합니다.
> 다른 팀원이 보낼 때는 그분의 사정에 맞게 이 한 줄만 바꿔 쓰십시오.
> (예: `이직을 준비하며 작은 서비스를 만들어 보고 있는 직장인`)
> 나중에 실제로 만나게 될 분들이라 여기서 어긋나면 그 관계가 먼저 깨집니다.

## 설정 바꾸기

스크립트 맨 위 설정만 고치고 다시 `전체생성`을 돌리면 새 폼이 생깁니다.

```js
var TEAM = ['이강호', '이민호', '손경필', '최종락', '한재익', '조정윤'];
var ROUNDS = ['10:00 회차', '14:00 회차', '17:00 회차'];
var SHOP_COUNT = 50;
```

**이미 만든 폼의 문항만 고치려면** 스크립트를 다시 돌리지 말고
`안내` 탭의 **편집용 링크**로 들어가 직접 수정하십시오. 다시 돌리면 폼이 하나 더 생깁니다.
